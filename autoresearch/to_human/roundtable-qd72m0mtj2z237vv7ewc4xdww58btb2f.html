1.  **Static Generation Bailout**: When `fetch()` is used with `cache: 'no-store'` within a prerendering context (e.g., during `next build`), it will cause a "bailout" from static generation, meaning the route will be rendered dynamically at request time instead of being prerendered at build time . This is because `no-store` indicates that the data should not be cached and must be fresh for every request, which is incompatible with static prerendering .

**Auth Provider Configuration (if using Composio or Pipedream)**
- Register your auth provider at [Airweave Auth Providers](https://app.airweave.ai/auth-providers) [^2]
- For **Composio**: Obtain your `auth_config_id` and `account_id` from the Composio dashboard [^2]
- For **Pipedream**: Set up *two* separate OAuth clients — one for Airweave-to-Pipedream API access, and one per source app (Notion, Google Drive, etc.) [^3]
  - Use **custom OAuth clients** only; Pipedream's built-in OAuth does not expose credentials [^3]
  - Note your `project_id`, `account_id`, and `external_user_id` for each connection [^3]

**OAuth 2.0 (Hosted MCP / Cloud Platforms)**
- The hosted MCP server supports OAuth 2.0 with PKCE via Auth0 — no manual setup needed for managed instances [^1]
- For self-hosted instances, OAuth is not available; use API key authentication only [^1]
